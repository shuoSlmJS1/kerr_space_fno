# Cross-resolution data definition: Plan B and Track A

This document defines the shared fixed-domain data used by Plan B FNO-only experiments and the Track A cross-model benchmark. Dataset names identify directories under `data/tasks/`, each containing `dataset.npz` and `meta.json`.

## 1. Task definition

- **Input physical parameter:** Q.
- **Input coordinate:** lambda, $\lambda$.
- **Target:** the trajectory $xyz(\lambda)$.

The task is $(Q,\lambda)\rightarrow xyz$. Track A normally represents a batch of trajectories as `(B,T,2) -> (B,T,3)`, with input channels `[Q, lambda]`. DeepONet organizes the same information into a **Q branch** and a **lambda trunk**; it receives no additional physical information.

## 2. Training datasets

The formal training sources are:

- T1200: `q_1p6-3_n2000_t1200`.
- T2399: `q_1p6-3_n2000_t2399_plan_b_matched_v1`.

| Item | T1200 | T2399 |
| --- | --- | --- |
| Q range | [1.6,3.0] | [1.6,3.0] |
| Q count | 2000 | 2000 |
| Train / validation / internal test | 1400 / 300 / 300 | 1400 / 300 / 300 |
| T | 1200 | 2399 |
| $\Delta\lambda$ | 0.005 | 0.0025 |
| Endpoint | 5.995 | 5.995 |
| Lambda range | [0,5.995] | [0,5.995] |

The two sources share the same uniform Q2000 identities, split membership, and within-split row ordering. The fine source replays the original split rather than drawing a new one. T2399 truth is generated by reintegration at the finer step, not interpolation of T1200 truth.

Ground truth is stored as `float64`; model computation uses `float32`. Each model fits normalization only on the train split at its own training resolution. The 1400 train trajectories support fitting, the 300 validation trajectories support model selection, and the 300 internal test trajectories are separate from the canonical Q400 evaluation datasets below. Frozen evaluation does not refit normalization.

## 3. Canonical Q400 evaluation datasets

| Dataset | T | $\Delta\lambda$ | Lambda range | Common-grid relation |
| --- | ---: | ---: | --- | --- |
| `q_1p6007-2p9993_n400_t1200` | 1200 | 0.005 | [0,5.995] | Coarse reference |
| `q_1p6007-2p9993_n400_t2399_plan_b_v1` | 2399 | 0.0025 | [0,5.995] | `[:,::2,:]` |
| `q_1p6007-2p9993_n400_t3598_plan_b_range_v1` | 3598 | 0.005/3 | [0,5.995] | `[:,::3,:]` |
| `q_1p6007-2p9993_n400_t4797_plan_b_range_v1` | 4797 | 0.00125 | [0,5.995] | `[:,::4,:]` |

All four datasets use Q range **[1.6007,2.9993]**, the same **400 uniform offset-grid Q identities**, and stored train/validation/test sizes of **280/60/60**. Formal evaluation merges **all 400 trajectories** and sorts Q and corresponding truth together into the same canonical ascending-Q order at every resolution.

This Q400 evaluation grid is distinct from the Q2000 training-source grid and lies within its Q range. The subsampling expressions in the table select coarse-coordinate nodes from trajectory arrays; they do not describe how the fine truth was generated.

## 4. Resolution construction

Refinement by factor r preserves both endpoints by using

$$
T_{\mathrm{fine}}=r(T_{\mathrm{coarse}}-1)+1,
\qquad
\Delta\lambda_{\mathrm{fine}}=\frac{\Delta\lambda_{\mathrm{coarse}}}{r}.
$$

For coarse T1200, r=2, 3, and 4 therefore give **T2399, T3598, and T4797**, respectively. In every case,

$$
\lambda_{\mathrm{endpoint}}=(T-1)\Delta\lambda=5.995.
$$

The physical sampling interval is fixed at **[0,5.995]**. Direct comparison of the stored coordinate arrays confirms:

- T2399 `lambda_grid[::2]` equals the coarse coordinates exactly.
- T4797 `lambda_grid[::4]` equals the coarse coordinates exactly.
- T3598 `lambda_grid[::3]` differs only at machine floating-point precision, with maximum absolute difference approximately $8.88\times10^{-16}$.

The T3598 discrepancy is numerical representation error, not a change in the physical interval. All four stored endpoints are 5.995.

## 5. Ground-truth pairing

Fine datasets are generated by reintegration using the same Q values, fixed physical parameters, initial conditions, and solver (`second_order_rk4`, version `v1`), with the smaller step size. They are **not interpolated coarse trajectories**. The paired generation workflows preserve source identities and split ordering.

Formal Q400 consistency validation compares fine truth subsampled onto coarse nodes against coarse truth. All three fine datasets have `structural_valid=true`.

| Fine dataset | Mean-per-Q common-grid truth Relative L2 |
| --- | ---: |
| T2399 | $5.22\times10^{-9}$ |
| T3598 | $5.49\times10^{-9}$ |
| T4797 | $5.53\times10^{-9}$ |

These numerical-truth differences are far smaller than the measured model errors, supporting their treatment as a negligible confounder in these comparisons. Coordinate pairing does not imply bitwise equality of independently integrated xyz truth.

## 6. Plan B versus Track A usage

### Plan B

Plan B uses matched n2000 T1200/T2399 training sources for FNO-only resolution generalization. Its initial historical T1200 checkpoint is evaluated on Q400 T1200/T2399; the bidirectional experiment adds matched T2399 training, and the later resolution-range experiment adds Q400 T3598/T4797 evaluation.

### Track A

Track A shares these data assets. Training uses **only n2000/T1200 or matched n2000/T2399**. All four Q400 datasets—T1200, T2399, T3598, and T4797—are used **only for frozen evaluation**, with the same Q identities and canonical order.

Although each Q400 file contains stored train/validation/test partitions, formal evaluation merges all 400 rows. **The Q400 partition named `train` is not used to train Track A models.** The shared assets serve different experimental comparisons: FNO-only transfer in Plan B and cross-model transfer in Track A.

## 7. Data format

The raw dataset format is:

```text
x_split:     (N,1)      Q values
lambda_grid: (T,)       shared lambda coordinates
y_split:     (N,T,3)    xyz ground truth
```

For ordinary Track A model batches:

```text
input  = [Q_broadcast, lambda]    (B,T,2)
target = xyz                      (B,T,3)
```

DeepONet organizes the same Q and lambda values as branch/trunk inputs. Historical Plan B FNO2D instead organizes the selected Q trajectories as a Q–lambda field, with input `(1,N,T,2)` and target `(1,N,T,3)`; the physical information is unchanged.

Ground truth is saved in **float64**. Training and inference use **float32**. Track A normalization statistics are accumulated and stored in **float64**, fitted on the corresponding train split only, and cast for the float32 application path. Frozen evaluation reuses those fitted statistics.

## 8. Important distinction from Plan A

| Experiment | Fixed | Changed |
| --- | --- | --- |
| Plan A | $\Delta\lambda=0.005$ | T and physical-domain length |
| Cross-resolution | Physical domain [0,5.995] | T and $\Delta\lambda$ |

Cross-resolution increases sampling density within the existing domain. Plan A extends the domain at unchanged sampling density. **Plan A T2400 long-domain data cannot substitute for T2399/T3598/T4797 cross-resolution data.**
